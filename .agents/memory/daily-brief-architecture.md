## What was built
Personalized 6-section daily marketing brief generated by Gemini, delivered in-app and by email at a user-configured local time.

## Tables (4 new, added to shared/schema.ts)
- `daily_brief_preferences` — per-user cadence/timezone/sendHour/email+in-app toggles, unique on userId
- `daily_briefs` — stored brief snapshots, unique index (userId, localDate), sectionsJson holds the 6 sections
- `daily_brief_deliveries` — channel delivery log (email/in-app), linked to brief
- `signup_competitor_intake` — queued competitor analysis for new signups; two-stage: created on signup, resolved when team is assigned

## Key files
- `lib/brief/assembler.ts` — assembleBriefContext() + scoreActions() (data gathering from 6+ tables in parallel)
- `lib/brief/generate-daily-brief.ts` — generateDailyBrief() calling Gemini with structured JSON schema; upserts via onConflictDoUpdate on (userId, localDate)
- `lib/brief-scheduler.ts` — startBriefScheduler() runs hourly, uses Intl.DateTimeFormat to match local hour to sendHourLocal
- `lib/worker.ts` — DAILY_BRIEF_QUEUE and SIGNUP_COMPETITOR_INTAKE_QUEUE workers registered in registerWorkers()
- `lib/email.ts` — sendDailyBriefEmail() added at end of file
- `app/api/briefs/today/route.ts` — returns {available, brief} for current user+date
- `app/api/briefs/preferences/route.ts` — GET/PATCH for cadence/timezone preferences
- `app/api/briefs/[id]/viewed/route.ts` — marks brief as viewed
- `app/api/briefs/generate-now/route.ts` — admin trigger for immediate generation
- `app/home/page.tsx` — DailyBriefCard shown at top for authenticated users
- `app/settings/brief/page.tsx` — preferences settings page
- `components/brief/DailyBriefCard.tsx` — 6-section card with collapsible sections
- `components/brief/BriefSkeleton.tsx` — loading skeleton
- `scripts/migrate-daily-brief.ts` — run with node --env-file=.env.local --import tsx/esm

## Architect gaps surfaced
- No time-series ranking data exists — "overnight movement" section uses article performance deltas as proxy
- Signup intake is two-stage: intake row created at signup time, resolved to team on admin approval
- shadcn `collapsible` and `skeleton` were not in the project — created manually at components/ui/

## BullMQ queues added
- `DAILY_BRIEF_QUEUE = "daily-brief"` — deduplication via jobId `daily-brief:{userId}:{localDate}`
- `SIGNUP_COMPETITOR_INTAKE_QUEUE = "signup-competitor-intake"` — 2 attempts, 30s exponential backoff

**Why:** Architect review found the existing modules (brand profiles, competitor discovery, learning patterns, performance metrics) were all siloed. The brief is a prioritization engine over data that already existed, not a new data source.
