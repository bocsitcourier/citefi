# Model upgrade architect investigation

Read-only source review. No paid provider calls or production changes. Current provider availability and DigitalOcean effective configuration were not verified.

**Verdict: FAIL for the expected automatic-upgrade behavior.** The implementation validates some configured IDs and replaces missing ones from fixed lists; it does not discover, rank, or promote newly released models. This is a read-only finding, not a recommendation to upgrade production now. `git status --short` and `git diff HEAD` showed no workspace changes; `lib/provider-cogs-ledger.ts` does not exist here (the authoritative ledger is `lib/provider-usage-ledger.ts`).

**High — exact decision path:** `lib/ai-config.ts:21-48` fixes each default or takes its environment override. `lib/model-resolver.ts:75-89,311-350` copies those values at worker startup, fetches Gemini `v1beta/models?pageSize=200` and OpenAI `/v1/models` once (`:174-265`), and, per tier with a nonempty chain, keeps the configured ID if listed; otherwise selects the *first listed ID in that tier’s hardcoded chain* (`:143-166,269-301`). Empty/failed discovery trusts the configured ID, not a newer candidate. No listed candidate for a critical tier causes startup failure; noncritical tiers retain an unrecognized configured ID. Veo has an empty chain and is never validated (`:149-150,338`); the experimental Gemini ID is only checked, not a resolved tier (`:199-208`). The Gemini request does not follow pagination or check supported operations. List membership is not proof of entitlement, generateContent support, or request compatibility.

**High — scenarios and divergent paths:** If the current configured flash/mini ID remains listed alongside a new ID, it stays selected indefinitely—even if that new ID is in the chain. If the configured ID disappears, the first live fixed-chain candidate wins; a new ID *outside* that chain is ignored (and critical tiers can fail startup). A listing outage retains the old ID. `reResolveAfterModelNotFound` (`lib/model-resolver.ts:363-370`) merely reruns the same algorithm; search found no caller, while `lib/errors.ts:155-173` classifies provider 404s as fatal. `server/worker-process.ts:136-143` resolves only in its own process; web-process `getModel` returns static defaults and warns (`lib/model-resolver.ts:97-116`), and `lib/openai-client.ts:310-316` only warns on web calls. Hardcoded calls bypass resolution entirely: `lib/content-review-service.ts:259-269`, `lib/openai-social.ts:121-131`, `lib/article-critique.ts:986-1008`, `lib/keyword-hyperlink-pipeline.ts:249-260`, and image/TTS paths (`lib/gemini-image-generator.ts:531-554`, `lib/openai-tts.ts:29-47`). Thus even a worker fallback does not upgrade these operations.

**High — unsafe to auto-promote without policy:** `lib/cost-telemetry.ts:28-69,312-325,382-395` uses a finite in-code rate map (unknown text price computes as zero); the locked authoritative ledger matches provider/model/unit/effective date exactly and marks missing rates unpriced with zero placeholder (`lib/provider-usage-ledger.ts:369-385`). Credits are reserved by operation/team menu, not model (`lib/billing.ts:162-176`); changing provider costs can break margins without adjusting reservations. OpenAI calls use chat completions, temperature, JSON mode and output limits (`lib/openai-social.ts:121-137`, `lib/openai-client.ts:247-261`); other paths require Gemini thinking/JSON/image modalities, TTS voices, or Veo’s separate API. Being listed cannot certify those contracts or prices.

**Medium — observability:** `/api/health` reports worker readiness’s `modelsReady` and release only (`app/api/health/route.ts:105-112`), not actual selected IDs, freshness, fallback, bypasses, or provider compatibility; the check can be skipped by feature policy (`lib/ops/health.ts:79-86,284-290`). No targeted resolver tests appeared in the test search. Source review cannot establish current account availability or newest provider versions; dated source comments are not evidence.

**Security:** None observed directly relevant to this investigation.

**Next actions:** (1) Establish admin-owned, per-capability approved candidates, explicit pins/rollback, provider pricing and tenant-wide cost policy before any promotion; avoid version-string ranking. (2) Centralize all call-site selection across web/worker and add read-only effective-selection diagnostics; handle confirmed model-specific 404s without replaying ambiguous paid requests. (3) Add offline mocked-list/SDK contract tests for retained IDs, new IDs, missing/partial lists, fallback, 404, process separation, hardcoded bypass inventory, compatibility, unknown pricing, and rollback; stage canaries before opt-in rollout.
